# 괴담 조사 — 프로토타입

서브컬처 쿼터뷰 익스트랙션 로그라이크의 웹 프로토타입. 스마트폰 가로 화면에서 D패드로 조작한다.

- 기획서: [docs/프로토타입_기획서.md](docs/프로토타입_기획서.md)
- 현재 단계: **4단계 덱 컨텐츠까지 구현** — 캐릭터 9명 중 3명을 골라 팀 편성부터 9섹터, 보스, 조사 팀(파티덱) 저장까지 한 런이 이어지고, 저장한 조사 팀으로 덱 컨텐츠에 도전한다
  - 도전 모드(파티덱 컨텐츠): 로비의 "도전 모드"에서 컨텐츠와 난이도를 먼저 고르고 출전할 조사 팀을 고른다. 특급 괴이 토벌(보스 타임어택, 시즌 1·2 보스, 난이도 5단계), 괴이 범람(웨이브 서바이벌). 덱별 최고 기록 저장
  - 테스트용 조사 팀 5개: 런을 돌지 않고도 도전 모드를 바로 시험할 수 있다 (`data/test_decks.csv`)
  - 캐릭터 9명(에트나 / 라이 / 키온 / 카렌 / 라온 / 유나 / 하루 / 로아 / 이브)과 고유 성장 48종, 펫 4종, 몬스터 6종 + 보스
  - 보상 3택 1(고유 성장 · 시즌 스킬 · 장비), 장비 스킬 21종, 수색 오브젝트, NPC 이벤트 6종, 경로 선택, 체크포인트 캠프, 상점
  - 섹터 사이 자동 저장과 이어하기, 일시정지 화면의 디버그 메뉴(무적, 섹터 클리어, 보상 받기 등)
  - 귀중품과 가방: 던전에서 주운 귀중품을 4칸 가방에 담아, 살아서 나가면 은화로 바뀐다. 주울 때 위험을 지는 선택이 있다 (기획서 7.12절)
  - 스프라이트 제작 도구와 스프라이트 표시부: 캐릭터 9명이 모두 스프라이트로 그려진다 (아래 "스프라이트 제작")
  - 이펙트: 조각 그림과 플립북으로 그리는 스킬·타격 이펙트 (아래 "이펙트 그림")
  - UI: 무채색 바탕에 라임 강조색 하나를 쓰는 규칙으로 통일 (기획서 4.1절, `src/styles/main.css` 맨 아래 "UI 규칙")
  - **마름모 화면 (시험판)**: 시즌 2를 마름모(아이소메트릭) 화면으로 다시 만든 판. 로비의 "시즌 2 · 마름모" 카드로 들어간다. 기존 시즌 1·2는 그대로다 (아래 "마름모 화면")

## 실행

```
npm install        처음 한 번
npm run dev        개발 서버 (같은 와이파이의 폰에서도 표시된 Network 주소로 접속 가능)
npm run build      배포용 빌드 (dist/)
npm test           규칙 코드 테스트 (화면 없이 테이블·맵 배치·섹터 자동 플레이 검사)
npm run smoke      빌드 결과를 브라우저로 열어 조작해 보고 스크린샷 저장 (tools/.out/)
node tools/isoshot.mjs    마름모 화면의 섹터들을 브라우저로 열어 스크린샷 저장 (tools/.out/iso/. 먼저 npm run build)
npm run art        스프라이트 제작 도구 (아래 "스프라이트 제작")
npm run sound      소리 제작 도구 (아래 "소리")
```

## 조작

| | 터치 | 키보드 |
| --- | --- | --- |
| 이동 | 방향 패드 (민 방향 그대로) | WASD / 방향키 (8방향) |
| 기본 공격 (누르는 동안 이동 정지) | 기본 공격 버튼 | J / Space |
| 회피 | 회피 버튼 | K / Shift |
| 액티브 | 액티브 버튼 | L / E |
| 궁극기 | 궁극기 버튼 | I / Q |
| 펫 스킬 | 펫 버튼 | O / R |
| 상호작용 (상자, 수색, 출구, NPC) | 캐릭터 오른쪽에 뜨는 버튼 | F |
| 교체 | 교체 캐릭터 카드 | 1 / 2 / 3 |
| 자동 공격 켜고 끄기 | 궁극기 버튼 위의 AUTO 버튼 | T |

자동 공격을 켜 두면 주변의 적에게 스스로 다가가 기본 공격과 액티브 스킬을 쓴다 (궁극기·펫·교체·회피·상호작용은 직접). D패드나 공격·회피 버튼을 누르는 동안에는 직접 조작이 먼저이고, 손을 떼면 바로 다시 자동으로 돌아온다. 주변에 적이 없으면 제자리에 선다. 규칙은 `src/game/player/auto.ts`, 수치는 `params.csv` 의 `auto.*` (기획서 3.9절).

근거리 캐릭터는 D패드를 누른 채 공격하면 그 방향으로, 누르지 않고 공격하면 추천 타겟(조준 표시가 붙은 적)에게 공격한다. 원거리 캐릭터는 D패드와 상관없이 항상 추천 타겟을 자동 조준한다 (`data/characters.csv` 의 aim).

## 수치 조정

수치는 전부 `data/` 폴더의 CSV에 있다. 엑셀이나 구글 시트로 고친 뒤 저장하면 된다.

- 엑셀에서는 **"CSV UTF-8 (쉼표로 분리)"** 형식으로 저장해야 한글이 깨지지 않는다.
- 다른 도구로 CSV를 새로 만들었다면 `node tools/csv-bom.mjs` 를 한 번 실행한다 (엑셀이 한글을 제대로 읽도록 파일 앞에 표식을 붙인다).
- 값이 빠졌거나 숫자가 아니면 게임을 시작할 때 "어느 파일 몇 번째 줄"인지 화면에 표시된다.
- 각 파일의 내용은 기획서 11.2절 참고.
- **도전 모드**: 컨텐츠는 `challenges.csv` 에 한 줄씩 적는다. 보스 토벌(kind = raid)은 season 만 적으면 그 시즌의 보스 섹터를 그대로 쓴다. 테스트용 조사 팀은 `test_decks.csv` 에서 팀·펫·받은 보상의 수(picks)와 품질(quality)을 고치면 빌드가 다시 만들어진다 (seed 를 바꾸면 다른 빌드).
- **시즌**: 섹터·몬스터 무리·시즌 스킬·장비 스킬·귀중품은 표의 season 칸으로 어느 시즌의 것인지 정한다. 시즌 자체는 `seasons.csv` 에 있다. 로비에서 고른 시즌의 것만 그 런에 나온다.
- **맵만 다른 시즌**: `seasons.csv` 의 base 칸에 다른 시즌의 번호를 적으면, 몬스터 무리·시즌 스킬·장비·귀중품·보스 음악은 그 시즌의 것을 쓰고 섹터(맵)만 제 것을 쓴다. 마름모 판(시즌 3)이 이렇게 시즌 2의 내용을 쓴다. label 칸은 로비에서 "시즌 N" 자리에 보여 줄 글이다.
- **화면 방식**: `sectors.csv` 의 view 칸이 `iso` 인 섹터는 마름모 화면으로, 비어 있으면 기존 화면으로 그린다. 마름모 화면의 확대 정도는 `params.csv` 의 `view.isoHeight`.
- **선택지가 뜨는 횟수**: 보상 상자는 무리마다 나오지 않고, 섹터마다 정한 수(`sectors.csv` 의 chests)만큼 몇 무리마다 하나씩 나온다. 시즌 하나에 고르는 선택지가 모두 30~35번쯤 되게 잡았고, `npx vitest run tests/choices.test.ts --silent=false` 가 종류별 횟수를 표로 보여 준다 (기획서 7.3절).
- **화면 분위기**: 맵을 어둡고 빛바래게 물들이는 정도는 맵 그림 세트마다 `moods.csv` 에 있다 (채도 sat, 먼 곳의 밝기 dark, 입히는 색 tint). 전체 세기는 `params.csv` 의 `mood.strength` (0이면 끈다).

## 맵

- 섹터 맵의 지형은 `data/maps/*.txt` 에 문자 격자로 고정돼 있다. 텍스트 편집기로 직접 고칠 수 있다.
- 입장할 때마다 엄폐 오브젝트·무리·수색 오브젝트·NPC만 규칙에 따라 무작위로 놓인다 (기획서 7.2절).

| 문자 | 의미 |
| --- | --- |
| `#` | 벽·건물 |
| `.` | 바닥. 엄폐 오브젝트가 무작위로 놓일 수 있다 |
| `_` | 통로. 항상 비워 둔다. 맵 그림 세트에 길 조각이 있으면(시즌 2의 노란 벽돌길) 이 칸에 길이 깔린다 |
| `S` `E` | 시작 / 출구 |
| `G` | 출구 수호 무리 (보스 맵에서는 보스 위치) |
| `M` `L` `N` | 무리 후보 / 수색 오브젝트 후보 / NPC 후보 |
| `X` `W` | 고정 장애물 / 웨이브 출현 지점 |

`npm run maps` 는 구역 설계도에서 맵 초안을 다시 생성한다. **손으로 고친 맵을 덮어쓰므로** 필요한 맵만 지정해서 쓴다 (`node tools/make-maps.mjs sector03`).

마름모 화면용 맵(`s3_*.txt`)은 `node tools/make-iso-maps.mjs [맵 이름]` 이 만든다. 문자의 뜻은 같고, 길을 놓는 방식만 다르다 (아래 "마름모 화면").

## 스프라이트 제작

원화 한 장에서 게임용 스프라이트 애니메이션까지 네 단계로 만든다.

| 단계 | 하는 일 | 쓰는 것 | 결과물 |
| --- | --- | --- | --- |
| 1. 기본 이미지 | 원화를 2.5등신 SD 캐릭터의 대기 자세로 그린다 (방향별 1장, 단색 배경) | Codex 이미지 생성 | `art/work/<id>/base_<방향>.png` |
| 2. 동작 영상 | 기본 이미지를 첫 프레임으로 동작 영상을 만든다 | Seedance 2.5 (BytePlus ModelArk) | `art/work/<id>/video/<동작>_<방향>.mp4` |
| 3. 프레임 | 영상에서 배경을 빼고, 쓸 구간을 찾아 프레임을 고르고, 발 위치와 크기를 맞춘다 | ffmpeg | `art/work/<id>/clips/<동작>_<방향>/` |
| 4. 시트 | 모든 동작의 프레임을 시트 이미지에 모은다 | | `public/sprites/<id>/` |

```
npm run art -- status                         무엇이 만들어져 있는지
npm run art -- all serin                      빠진 단계의 계획과 예상 비용만 보여 준다
npm run art -- all serin --only Idle,Move --yes    실제로 만든다 (영상 생성은 요금이 든다)
npm run art -- clip serin Move SE --from 0.5 --to 1.2    자동으로 잡은 구간이 어색하면 초 단위로 직접 지정
npm run art -- still serin                    영상 없이 기본 이미지 한 장을 정지 대기 동작으로 쓴다 (요금 없음)
npm run art -- pack serin                     프레임을 고친 뒤 시트만 다시 만든다
```

- **준비물**: Codex CLI 로그인(`codex login`), `.env.local` 의 `ARK_API_KEY`(BytePlus ModelArk), ffmpeg. `.env.local` 은 저장소에 올라가지 않는다.
- **비용**: 영상 한 편(1:1, 480p, 4초)이 Seedance 2.5 기준 약 0.42달러다 (캐릭터 한 명의 동작 10종이 약 4.2달러). `all` 은 `--yes` 없이는 아무것도 만들지 않고 계획과 예상 비용만 보여 준다. 이미 만든 것은 건너뛴다. Codex 이미지 생성은 ChatGPT 요금제 사용량에서 차감된다.
- **프레임 수 바꾸기**: `clips.csv` 의 frames 를 고치고 `clip` → `pack` 만 다시 돌린다. 영상을 다시 만들지 않으므로 요금이 들지 않는다.
- **무기가 잘릴 때**: 3단계에서 "그림이 영상 가장자리에 닿았습니다"가 나오면 휘두른 무기가 화면 밖으로 나간 것이다. `settings.csv` 의 `video.inset` 을 줄이고(여백이 넓어진다) `video <id> <동작> --force` 로 그 영상만 다시 만든다.
- **영상 없이 먼저 넣어 보기**: 기본 이미지만 만들고 `still` → `pack` 을 하면 정지 그림으로 게임에 들어간다. 그림체와 크기를 먼저 확인한 뒤 영상을 만들 수 있다.
- **확인**: 3단계가 끝나면 프레임 폴더에 `preview.gif`(움직임)와 `preview.png`(프레임 나열, 노란 선이 발밑)가 생긴다.
- **게임 반영**: 4단계가 끝나면 `public/sprites/index.json` 에 등록되고, 등록된 캐릭터·몬스터만 스프라이트로 그려진다. 아직 없는 동작은 가까운 동작으로 대신한다 (예: 이동 그림이 없으면 대기 그림).
- **표**: `data/art/` 의 CSV에서 고친다.

| 파일 | 내용 |
| --- | --- |
| subjects.csv | 만들 대상. 원화 파일, 배경색(캐릭터에 없는 색), 게임에서의 키, 방향, 외형·무기 설명 |
| clips.csv | 동작 목록. range 칸 뒤에 `!1.03-1.31` 처럼 붙이면 그 구간(초)의 프레임은 쓰지 않는다 (영상에 들어간 총구 화염 등). 반복 여부, 구간 찾는 방식, 프레임 수, 재생 속도, 영상 길이, 타격 지점(auto 면 가장 빠르게 움직이는 순간), 끝 프레임 고정 여부, 발 높이 보정 여부, 영상 속 이펙트(trail 이면 흰 검기 허용), 동작 설명. who 칸에 캐릭터 id를 적으면 그 캐릭터만의 동작이 된다. `BasicAttack1`, `BasicAttack2` …는 기본 공격 연속기의 단계별 동작이다 |
| settings.csv | 영상 모델·해상도·여백, 배경 제거 세기, 프레임 고르는 방식, 시트 크기 |

원화(`art/ref/`)와 영상 원본(`art/work/*/video/*.mp4`), 잘라낸 프레임은 용량과 공개 범위 때문에 저장소에 올리지 않는다. 영상을 지우면 다시 만들 때 요금이 드니 따로 보관한다.

방향은 화면 기준 이름이다 (`S` = 아래쪽, 카메라를 향함). 지금은 앞쪽 사선(`SE`) 한 방향만 만들고 좌우 반전해 쓴다. subjects.csv 의 dirs 에 방향을 더 적으면(예: `SE NE`) 그 방향 그림도 만든다.

### 펫

펫은 공통 베이스 바디에 스킬에 맞는 의상과 소품을 입혀 만든다 (기획서 6.1절).

```
npm run art -- image pet_a --force     디자인 다시 생성 (Codex. 요금 없음). 편성 화면용 그림(cutout.png)도 함께 만든다
npm run art -- still pet_a             영상 없이 정지 그림 한 장으로 게임에 넣는다
npm run art -- pack pet_a && npm run art -- ui
```

- 설계(의상, 소품, 대표색)는 `data/art/subjects.csv` 의 design 칸에 적는다. ref 칸의 `pet_base.png` 가 베이스 바디다.
- 그림체는 `image.petStyleRef`(기준 펫)의 원화에 맞춘다. 원화(`art/ref/`)는 저장소에 올리지 않으므로, 없으면 기준 펫의 기본 이미지를 대신 쓴다.

### 몬스터

몬스터도 캐릭터와 같은 순서로 만든다: 외형 설명 → 기본 이미지(Codex) → 동작 영상(Seedance) → 시트.
**영상은 요금이 들고 기본 이미지가 모든 동작의 첫 프레임이 되므로, 겉모습을 확정한 뒤에 만든다.** 그 전까지는 정지 그림 한 장으로 게임에 넣어 맵 위에서 어울리는지 본다.

```
npm run art -- image tinman [--force]   기본 이미지 (Codex. 요금 없음)
npm run art -- still tinman             영상 없이 정지 그림 한 장으로
npm run art -- pack tinman              public/sprites/tinman/ 에 놓는다. 게임에 바로 반영된다
npm run art -- all tinman               (겉모습 확정 뒤) 빠진 동작의 계획과 예상 비용. --yes 를 붙여야 실제로 만든다
npm run art -- video tinman Death --force    동작 하나만 다시 만든다 (요금 발생). 이어서 clip tinman Death → pack tinman
```

**`all` 에 `--force` 를 붙이지 않는다.** 기본 이미지까지 다시 만들어 확정한 겉모습이 바뀐다. 동작 하나를 다시 만들 때는 위의 `video … --force` 를 쓴다.

- 외형은 `data/art/subjects.csv` 에 kind = monster 로 적는다 (id 는 `data/monsters.csv` 의 id 와 같아야 한다). height 는 게임 안에서의 키(px. 캐릭터는 74~84).
- 그림체는 캐릭터의 기준 스프라이트(`image.styleRef`)를 함께 보여 줘서 맞춘다: 같은 선, 같은 셀 채색, 같은 시점.
- 동작 그림이 없는 동안에는 공격 준비를 몸이 부풀며 붉어지는 것으로, 죽음을 납작해지며 사라지는 것으로 대신 보여 준다.
- **동작 목록**은 `data/art/clips.csv` 의 kind = monster 줄이다. who 가 `*` 인 줄이 공용이고, 몬스터 id 를 적은 줄이 그 몬스터의 것이다 (움직임을 그 몬스터의 생김새에 맞춰 영어로 적는다). 공용 줄의 동작을 어떤 몬스터에게는 만들지 않으려면 그 몬스터의 줄을 range = `none` 으로 둔다 (보스의 Hit).
- 게임이 쓰는 동작: Idle, Move, MonsterAttack, Hit, Death. 행동 규칙에 따라 Pattern(허수아비가 도는 동작, 보스의 시전), 보스 전용 Finale·Phase 가 더 있다. 어느 규칙이 어느 동작을 쓰는지는 `src/game/enemy/ai.ts`, `witch.ts` 의 `setAnim` 을 본다.
- **화면 속 크기**: 기본 이미지에 잡힌 크기가 몬스터마다 다르므로(늑대는 화면의 30%, 보스는 80%), 영상의 첫 프레임에는 몸의 키가 정해진 범위에 들도록 키우거나 줄여 넣는다 (`settings.csv` 의 `video.bodyLoopMin/Max`, `video.bodyActionMin/Max`, `video.marginLoop/Action`). 너무 작으면 영상 모델이 동작 장면에서 확대 컷으로 넘어가 크기가 튀고, 너무 크면 움직일 자리가 없어 잘린다.
- **타격 지점**: 공격 동작은 게임에서 예고 시간에 맞춰 재생된다. 준비가 끝나고 내지르는 순간이 타격 지점(impact)이고, 그 프레임이 예고가 끝나는 순간에 온다. `auto` 는 가장 빠르게 움직이는 순간을 고르는데, 영상 끝에서 대기 자세로 급히 돌아오는 순간을 잘못 고르는 일이 있다. `clips/<동작>_SE/preview.png` 와 `clip.json` 의 프레임별 시점(t)을 보고 어긋나면 표의 impact 칸에 0~1 숫자를 직접 적은 뒤 `pack` 만 다시 한다.
- **쓰지 말아야 할 지시**: "연기로 흩어져 사라진다" 같은 반투명한 효과는 단색 배경 위에서 지저분한 얼룩으로 남는다. 죽음은 "쓰러져 가만히 있다"로 끝내고, 사라지는 것은 게임이 한다. "뛰어든다"처럼 화면 안에서 이동하는 움직임은 "뒷발은 제자리에 둔 채 앞몸을 내민다"처럼 제자리에서 하는 것으로 적는다.

## 맵 그림

맵의 바닥·지붕·벽 질감과 오브젝트는 Codex 이미지 생성으로 만든다. 영상은 쓰지 않는다.

```
npm run art -- scenery                 빠진 것만: 이미지 생성 → 자르기 → 묶기 (모든 세트)
npm run art -- scenery --set oz_field  세트 하나만 (쉼표로 여러 개)
npm run art -- scenery gen props1 --set oz_forest --force    그 세트의 그 시트만 다시 생성
npm run art -- scenery cut             시트를 물체별로 자르고 크기를 맞춘다 (art/scenery/<세트>/preview.png 로 확인)
npm run art -- scenery pack            게임이 읽는 public/scenery/<세트>/ 를 만든다
```

- **세트** = 한 가지 분위기의 맵 그림 한 벌. `data/art/scenery_sets.csv` 에 세트마다 배경 설정(theme), 그림체·색 지시문(objectStyle, thingStyle), 색 보정, 지붕 가장자리 색·맵 바깥 색, 길이 깔릴 확률(road)을 적는다. 지금 있는 세트: `alley`(시즌 1), `oz_field` / `oz_forest` / `oz_stage`(시즌 2), `oz`(시즌 2의 세 세트가 함께 쓰는 상호작용 오브젝트·문·노란 벽돌길. include 칸으로 포함된다).
- 섹터가 어느 세트를 쓰는지는 `data/sectors.csv` 의 scene 칸. 새 테마의 맵은 세트 한 줄과 그 세트의 시트·물체 줄을 더해 만든다.

- 여러 물체를 한 장에 격자로 그려 받아 잘라 쓴다. 시트는 `data/art/scenery_sheets.csv`, 시트 안의 물체와 게임에서의 크기는 `data/art/scenery.csv` 에 적는다.
- 크기만 바꿀 때는 표의 size 를 고치고 `cut` → `pack` 만 다시 돌린다 (이미지를 다시 생성하지 않는다).
- 오브젝트 시트는 그 세트의 바닥 질감(세트 표의 styleRef)을 기준 그림으로 함께 넘겨 그림체와 색을 바닥에 맞춘다. 글로벌 서비스이므로 한 나라에 고유한 물건은 넣지 않는다.
- 색이 바닥과 따로 놀면 세트 표의 grade(바닥 색조로 물들이는 정도)와 gradeSat(채도 배율)을 고치고 `cut` → `pack` 만 다시 돌린다. `art/scenery/<세트>/preview.png` 는 실제 바닥 위에 오브젝트를 늘어놓은 그림이다.
- 물체 줄의 opt 칸에 `stand` 를 적으면 바닥에 눕히지 않고 세워서 그린다 (서 있는 문, 포자 버섯).
- `public/scenery/<세트>/` 가 없으면 게임은 그 세트의 맵을 도형으로 그린다.

## 마름모 화면

시즌 2를 마름모(아이소메트릭 2:1) 화면으로 다시 만든 시험판이다. 로비에서 "시즌 2 · 마름모" 카드를 고르면 들어간다.
캐릭터·몬스터·보상·규칙은 시즌 2와 같고, 맵과 보는 방식만 다르다. 기존 시즌 1·2의 맵과 화면은 건드리지 않았다.

- **보는 방식만 다르다**: 규칙 코드(`src/game/`)는 기존과 같은 네모 격자 위에서 움직인다. 표시부가 그 좌표를 화면에 놓을 때만 방식을 바꾼다 (`src/render/proj.ts`). 맵의 +x 가 화면 오른쪽 아래로, +y 가 왼쪽 아래로 간다.
- **조작**: 방향 패드는 화면 기준이다. 민 방향 그대로 화면에서 움직이고, 길이 놓인 각도(가로 2 : 세로 1, 약 27도)로 밀면 길을 따라 걷는다. 화면에서 옆으로 걷는 빠르기는 기존과 같고, 위아래로는 절반으로 보인다. 키보드는 8방향뿐이라 대각선이 길과 나란하도록 45도 돌려서 받는다 (`src/render/proj.ts` 의 worldDir / inputX·inputY).
- **벽의 높이**: 뒤쪽(화면 위쪽)에 걸어 다니는 바닥이 없는 벽은 높이 세우고, 뒤쪽 가까이에 바닥이 있는 벽은 낮게 자른다. 그래서 캐릭터와 몬스터가 벽에 가려지지 않는다 (`src/render/isoWalls.ts`, `npm test` 가 모든 마름모 맵에서 확인한다). 벽 위의 나무·건물도 바닥을 가리지 않는 자리에만 선다.
- **맵을 놓는 법**: 길을 "동(+x)으로 조금, 북(-y)으로 조금"을 번갈아 가는 계단 모양으로 놓는다. 화면에서는 왼쪽에서 오른쪽으로 지그재그로 나아가는 길이 되고, 길의 뒤쪽은 언제나 높은 벽과 구조물이 배경처럼 늘어선다. `tools/make-iso-maps.mjs` 맨 위에 문법이 있다 (방 `room`, 길 `E` / `N`, 곁방 `pocket`, 표식 `mark`).
- **그림**: 바닥·노란 벽돌길·바닥 장식·엄폐 오브젝트·상호작용 오브젝트는 기존 맵 그림을 그대로 쓴다 (바닥은 기울여 깔고, 한쪽으로 긴 오브젝트는 차지한 칸의 방향에 맞춰 기울인다). 높은 벽의 앞면은 기존 벽 질감의 원본을 통째로 쓰고, 벽 위의 구조물(나무·오두막·풍차·조명탑 …)만 마름모 각도로 새로 그렸다.

```
npm run art -- iso                    빠진 것만: 이미지 생성(Codex. 요금 없음) → 자르기 → 묶기
npm run art -- iso gen --set oz_field --force    그 세트의 구조물 시트를 다시 생성
npm run art -- iso cut                시트를 구조물별로 자르고 크기를 맞춘다 (art/iso/<세트>/preview.png 로 확인)
npm run art -- iso pack               게임이 읽는 public/iso/<세트>/ 를 만든다
```

- 무엇을 그릴지는 `data/art/iso_sheets.csv`(시트)와 `data/art/iso.csv`(구조물: 차지하는 칸 수 tw·th, 게임에서의 너비 size, 높은 벽 한 칸마다 설 확률 rate, 빛의 색 glow)에 적는다. 세트 이름은 맵 그림 세트와 같고, 그림체 지시문도 그 세트의 것을 쓴다.
- 구조물이 너무 많거나 적으면 rate 만 고치고 `pack` 을 다시 한다. 크기는 size 를 고치고 `cut` → `pack`.
- 벽 앞면을 새로 그리고 싶으면 `art/iso/<세트>/face.png` 에 정사각형 그림을 놓는다 (없으면 `art/scenery/<세트>/wall.png` 를 쓴다). 가로로만 이어 붙는다.
- `public/iso/<세트>/` 가 없으면 마름모 맵은 기존 벽 질감만으로 그려진다.
- **이펙트**: 규칙 코드는 이펙트의 좌표를 "바닥의 점 + 높이(h)"로 알린다. 그래서 같은 이펙트가 두 화면에서 모두 제자리에 놓인다. 이펙트를 새로 만들 때의 약속은 `src/render/fxRecipes.ts` 맨 위에 있다 (조준 방향은 `dir`, 바닥과 나란히 퍼지는 것은 `flat`).
- **확인**: `npm run build && node tools/isoshot.mjs` 가 섹터마다 시작 지점·전투·출구를 찍어 `tools/.out/iso/` 에 저장한다 (`--season 2` 를 붙이면 견줄 수 있게 기존 화면을 찍는다).

## 이펙트 그림

이펙트는 그림 한 장짜리 **조각**을 코드가 움직여 그리는 것이 기본이고, 대표 궁극기만 영상에서 뽑은 **플립북**을 쓴다.

```
npm run art -- fx                    빠진 것만: 조각 이미지 생성 → 자르기 → 묶기 (요금 없음)
npm run art -- fx gen fx_slash --force    그 시트만 다시 생성
npm run art -- fx cut                시트를 조각으로 자른다 (art/fx/preview.png 로 확인)
npm run art -- fx pack               게임이 읽는 public/fx/ 를 만든다
npm run art -- fx flip               플립북의 계획과 예상 비용 (--yes 를 붙여야 영상을 만든다. 편당 요금 발생)
npm run build && node tools/fxshot.mjs [캐릭터 id …]    캐릭터별 스킬 이펙트를 찍어 한 장으로 모은다 (tools/.out/fx/)
```

- 조각은 검은 바탕에 흰 빛으로 그려 받아 밝기를 불투명도로 바꾼다. 게임에서 캐릭터 색을 입히고, 가장 밝은 부분만 남긴 흰 심지를 겹쳐 그린다.
- 무엇을 그릴지는 `data/art/fx_sheets.csv`(시트: lum 흰 빛 / color 색 있는 빛 / key 단색 배경의 물체), `data/art/fx.csv`(조각. size 는 게임에서 긴 변의 길이, rot·flip 으로 방향을 바로잡는다), `data/art/fx_flips.csv`(플립북)에 적는다.
- 이펙트가 어떻게 보일지는 `src/render/fxRecipes.ts` 에서 고친다. 규칙 코드는 `w.fx.play('raon.slam', x, y, { size })` 처럼 이름으로만 부른다. 좌표 (x, y)는 언제나 바닥의 한 점이고, 몸 가운데나 머리 위처럼 띄워 그릴 것은 높이 `h` 로 따로 넘긴다. 새 이펙트는 이 파일에 이름을 추가하고 규칙 코드에서 같은 이름으로 부르면 된다 (`npm test` 가 이름과 그림이 맞는지 검사한다).
- `public/fx/` 가 없으면 예전의 도형 이펙트가 나온다. 플립북 영상 원본(`art/fx/flip/*/video.mp4`)은 저장소에 올리지 않는다.

## 소리

효과음, 징글, 배경 음악, 환경음을 ElevenLabs 로 만든다. `.env.local` 에 `ELEVENLABS_API_KEY=키` 가 있어야 하고 ffmpeg 가 설치돼 있어야 한다.
언제 어떤 소리가 나는지와 재생 규칙은 기획서 11.4절 참고.

```
npm run sound -- status                  무엇이 만들어져 있는지
npm run sound -- make                    아직 없는 소리의 계획과 예상 크레딧만 보여 준다
npm run sound -- make --yes              실제로 만든다 (크레딧이 든다. 1초에 10크레딧)
npm run sound -- make hit.blade1 --force --yes    마음에 들지 않는 소리를 다시 만든다 (같은 지시문이어도 매번 다르게 나온다)
npm run sound -- make --changed --yes    표의 지시문·길이를 고친 소리만 다시 만든다
npm run sound -- process                 원본에서 다시 다듬는다 (요금 없음. 크기 기준 같은 설정을 고쳤을 때)
npm run sound -- check                   결과물의 길이, 크기, 반복 이음매, 박자의 빠르기를 잰다
```

| 표 (`data/sound/`) | 내용 |
| --- | --- |
| sounds.csv | 만들 소리: 이름, 종류, 길이(초), 지시문(영어). gain 은 그 소리만 키우거나 줄이는 값(dB) |
| cues.csv | 게임에서 일어난 일 → 낼 소리, 크기, 높낮이 변화, 다시 날 수 있는 간격 |
| bgm.csv | 장소 → 배경 음악과 환경음, 각각의 크기 (volume, ambVolume) |
| settings.csv | 모델, 크기 기준, 무음을 자르는 기준 |

- **종류(kind)**: `sfx` 한 번 나는 효과음 (한 채널) / `jingle` 짧은 음악 (두 채널) / `loop` 끊김 없이 반복되는 소리 (환경음과 배경 음악. 30초까지) / `music` 음악 모델로 만드는 긴 곡 (**유료 요금제에서만** API 로 쓸 수 있다. 도구가 마디에 맞춰 반복 구간을 잘라 낸다).
- **소리를 새로 넣을 때**: `sounds.csv` 에 한 줄을 적고 `make --yes` → `cues.csv` 에 "언제 낼지"를 한 줄 적는다. 규칙 코드가 이미 알리고 있는 일이면 코드는 고치지 않는다. 새 일이면 규칙 코드에서 `w.fx.sound('이름', x, y, 종류)` 로 알린다 (이름으로 부르는 이펙트 `w.fx.play` 는 같은 이름의 소리를 함께 낸다).
- **종류별 소리**: 일에 종류(무기 종류, 발사체 종류, 몬스터 id)가 딸려 오면 `cues.csv` 에서 "이름.종류" 줄을 먼저 찾고, 없으면 "이름" 줄을 쓴다 (`hit.greatsword` → `hit`).
- **소리 크기**: 한 소리만 크거나 작으면 `cues.csv` 의 volume 을 고친다 (다시 만들 필요 없음). 환경음이 음악을 덮으면 `bgm.csv` 의 ambVolume 을 낮춘다 (음악과 환경음은 같은 크기로 다듬어져 있어 volume 과 ambVolume 의 비가 곧 둘의 크기 비다. 바람 소리는 음악의 1/4 쯤이 알맞다). 전체 균형은 `params.csv` 의 `sound.*`.
- **배경 음악의 빠르기**: 반복 구간이 마디 중간에서 끊기지 않게, 지시문의 BPM 은 "길이가 마디의 정수배가 되는 값"으로 적는다. 30초라면 128 BPM(16마디), 96 BPM(12마디), 160 BPM(20마디), 3/4박자 144 BPM(24마디). `check` 가 만들어진 곡의 빠르기와 마디 수를 보여 준다.
- **지시문**: 무슨 물건이 어떻게 움직여 나는 소리인지 한 문장으로 적고, 끝에 빼고 싶은 것을 적는다 ("No voice, no music"). 한 번만 나야 하는 소리는 "one" 을 적는다. 배경 음악은 장르, BPM, 조, 악기를 차례로 적고 "Full arrangement the whole time" 을 붙인다 (없으면 코드만 길게 울리는 빈 곡이 나온다).
- **들어 보기**: 게임과 함께 `sound/` 페이지가 올라간다 (`https://<계정>.github.io/tarcov/sound/`, 개발 서버에서는 `/sound/index.html`). 소리를 하나씩 듣고 "다시"에 표시하면 다시 만들 목록이 아래에 모인다.
- 만든 원본은 `art/sound/raw/` 에, 게임이 읽는 결과물은 `public/sound/` 에 놓인다. 원본이 있으면 다듬기만 다시 할 수 있다.
- **이용 조건**: 지금 소리는 ElevenLabs 무료 요금제로 만들었다 (elevenlabs.io). 무료 요금제의 결과물은 상업적으로 쓸 수 없으므로, 출시할 때는 유료 요금제에서 다시 만든다 (`make --force --yes`).

## 폴더 구조

```
art/             그림 원본: 원화(ref/), 캐릭터 기본 이미지·영상·프레임(work/), 맵 그림 시트(scenery/), 마름모 맵의 구조물 시트(iso/), 이펙트 시트(fx/)
  sound/raw/     만든 소리의 원본과 기록
data/            수치 테이블(CSV)과 고정 맵
  art/           스프라이트 제작 표
  sound/         소리 표 (만들 소리, 언제 낼지, 배경음)
public/sprites/  게임이 읽는 스프라이트 시트
public/scenery/  게임이 읽는 맵 그림
public/iso/      게임이 읽는 마름모 맵 그림 (높은 벽의 앞면, 벽 위의 구조물)
public/fx/       게임이 읽는 이펙트 그림 (조각, 플립북)
public/sound/    게임이 읽는 소리와 목록, 들어 보는 페이지(index.html)
docs/            기획서
src/
  audio/         소리: 재생(audio.ts), 표 읽기(tables.ts), 섞기 계산(mix.ts)
  core/          난수, 수학, CSV 파서
  data/          테이블 읽기·검사
  game/          규칙 (화면을 그리지 않는다)
    world/       맵, 충돌, 무작위 배치, 전투 월드
    player/      파티 조작, 캐릭터 상태, 캐릭터별 스킬(kits/)
    enemy/       몬스터 상태와 행동 규칙
    pet/         펫 스킬
    run/         런 상태, 능력치 계산, 섹터 구성
  render/        PixiJS 표시부
    views/       캐릭터·몬스터 표시부 (도형 플레이스홀더와 스프라이트). registry.ts 가 고른다
    sprites/     스프라이트 시트 읽기, 방향·프레임 선택
    fx*.ts       이펙트: 재생(fx.ts), 그림 읽기(fxArt.ts), 이름별 조합(fxRecipes.ts)
    proj.ts      화면 방식(기존 / 마름모)에 따른 좌표 변환
    mood*.ts     화면 분위기: 세트별 수치(mood.ts), 맵을 어둡게 물들이는 셰이더(moodFilter.ts)
    iso*.ts      마름모 화면: 맵 그리기(isoMapView.ts), 벽 높이 규칙(isoWalls.ts), 그림 읽기(isoArt.ts)
  input/         터치·키보드 입력
  ui/            HUD와 메뉴 (HTML 오버레이)
tests/           규칙 코드 테스트
tools/           맵 생성(make-maps.mjs, 마름모용 make-iso-maps.mjs), 브라우저 확인 도구(smoke.mjs, fxshot.mjs, isoshot.mjs), 스프라이트 제작 도구(art/), 소리 제작 도구(sound/)
```

규칙 코드(`src/game/`)는 화면·소리와 분리돼 있어, 그림이나 소리를 바꿔도 규칙 코드는 건드리지 않는다. 스프라이트 시트가 등록된 캐릭터는 스프라이트로, 나머지는 도형으로 그려진다.

## 배포

`main` 브랜치에 푸시하면 GitHub Actions가 테스트·빌드한 뒤 결과물을 `gh-pages` 브랜치에 올린다.
GitHub 저장소 설정의 Pages에서 `gh-pages` 브랜치를 소스로 지정하면 `https://<계정>.github.io/tarcov/` 로 접속할 수 있다.
