# 괴담 조사 — 프로토타입

서브컬처 쿼터뷰 익스트랙션 로그라이크의 웹 프로토타입. 스마트폰 가로 화면에서 D패드로 조작한다.

- 기획서: [docs/프로토타입_기획서.md](docs/프로토타입_기획서.md)
- 현재 단계: **4단계 덱 컨텐츠까지 구현** — 캐릭터 9명 중 3명을 골라 팀 편성부터 9섹터, 보스, 조사 팀(파티덱) 저장까지 한 런이 이어지고, 저장한 조사 팀으로 덱 컨텐츠에 도전한다
  - 파티덱 컨텐츠 2종: 특급 괴이 토벌(보스 타임어택, 난이도 5단계), 괴이 범람(웨이브 서바이벌). 덱별 최고 기록 저장
  - 캐릭터 9명(서린 / 미도 / 시아 / 카렌 / 라온 / 유나 / 하루 / 로아 / 이브)과 고유 성장 48종, 펫 4종, 몬스터 6종 + 보스
  - 보상 3택 1(고유 성장 · 시즌 스킬 · 장비), 장비 스킬 21종, 수색 오브젝트, NPC 이벤트 6종, 경로 선택, 체크포인트 캠프, 상점
  - 섹터 사이 자동 저장과 이어하기, 일시정지 화면의 디버그 메뉴(무적, 섹터 클리어, 보상 받기 등)
  - 스프라이트 제작 도구와 스프라이트 표시부: 그림이 준비된 캐릭터·동작부터 도형 플레이스홀더를 대신한다 (아래 "스프라이트 제작")

## 실행

```
npm install        처음 한 번
npm run dev        개발 서버 (같은 와이파이의 폰에서도 표시된 Network 주소로 접속 가능)
npm run build      배포용 빌드 (dist/)
npm test           규칙 코드 테스트 (화면 없이 테이블·맵 배치·섹터 자동 플레이 검사)
npm run smoke      빌드 결과를 브라우저로 열어 조작해 보고 스크린샷 저장 (tools/.out/)
npm run art        스프라이트 제작 도구 (아래 "스프라이트 제작")
```

## 조작

| | 터치 | 키보드 |
| --- | --- | --- |
| 이동 | D패드 | WASD / 방향키 |
| 기본 공격 (누르는 동안 이동 정지) | 기본 공격 버튼 | J / Space |
| 회피 | 회피 버튼 | K / Shift |
| 액티브 | 액티브 버튼 | L / E |
| 궁극기 | 궁극기 버튼 | I / Q |
| 펫 스킬 | 펫 버튼 | O / R |
| 상호작용 (상자, 수색, 출구, NPC) | 캐릭터 오른쪽에 뜨는 버튼 | F |
| 교체 | 교체 캐릭터 카드 | 1 / 2 / 3 |

근거리 캐릭터는 D패드를 누른 채 공격하면 그 방향으로, 누르지 않고 공격하면 추천 타겟(조준 표시가 붙은 적)에게 공격한다. 원거리 캐릭터는 D패드와 상관없이 항상 추천 타겟을 자동 조준한다 (`data/characters.csv` 의 aim).

## 수치 조정

수치는 전부 `data/` 폴더의 CSV에 있다. 엑셀이나 구글 시트로 고친 뒤 저장하면 된다.

- 엑셀에서는 **"CSV UTF-8 (쉼표로 분리)"** 형식으로 저장해야 한글이 깨지지 않는다.
- 다른 도구로 CSV를 새로 만들었다면 `node tools/csv-bom.mjs` 를 한 번 실행한다 (엑셀이 한글을 제대로 읽도록 파일 앞에 표식을 붙인다).
- 값이 빠졌거나 숫자가 아니면 게임을 시작할 때 "어느 파일 몇 번째 줄"인지 화면에 표시된다.
- 각 파일의 내용은 기획서 11.2절 참고.

## 맵

- 섹터 맵의 지형은 `data/maps/*.txt` 에 문자 격자로 고정돼 있다. 텍스트 편집기로 직접 고칠 수 있다.
- 입장할 때마다 엄폐 오브젝트·무리·수색 오브젝트·NPC만 규칙에 따라 무작위로 놓인다 (기획서 7.2절).

| 문자 | 의미 |
| --- | --- |
| `#` | 벽·건물 |
| `.` | 바닥. 엄폐 오브젝트가 무작위로 놓일 수 있다 |
| `_` | 통로. 항상 비워 둔다 |
| `S` `E` | 시작 / 출구 |
| `G` | 출구 수호 무리 (보스 맵에서는 보스 위치) |
| `M` `L` `N` | 무리 후보 / 수색 오브젝트 후보 / NPC 후보 |
| `X` `W` | 고정 장애물 / 웨이브 출현 지점 |

`npm run maps` 는 구역 설계도에서 맵 초안을 다시 생성한다. **손으로 고친 맵을 덮어쓰므로** 필요한 맵만 지정해서 쓴다 (`node tools/make-maps.mjs sector03`).

## 스프라이트 제작

원화 한 장에서 게임용 스프라이트 애니메이션까지 네 단계로 만든다.

| 단계 | 하는 일 | 쓰는 것 | 결과물 |
| --- | --- | --- | --- |
| 1. 기본 이미지 | 원화를 2.5등신 SD 캐릭터의 대기 자세로 그린다 (방향별 1장, 단색 배경) | Codex 이미지 생성 | `art/work/<id>/base_<방향>.png` |
| 2. 동작 영상 | 기본 이미지를 첫 프레임으로 동작 영상을 만든다 | Seedance 2.5 (BytePlus ModelArk) | `art/work/<id>/video/<동작>_<방향>.mp4` |
| 3. 프레임 | 영상에서 배경을 빼고, 쓸 구간을 찾아 프레임을 고르고, 발 위치와 크기를 맞춘다 | ffmpeg | `art/work/<id>/clips/<동작>_<방향>/` |
| 4. 시트 | 모든 동작의 프레임을 시트 이미지에 모은다 | | `public/sprites/<id>/` |

```
npm run art -- status                         무엇이 만들어져 있는지
npm run art -- all serin                      빠진 단계의 계획과 예상 비용만 보여 준다
npm run art -- all serin --only Idle,Move --yes    실제로 만든다 (영상 생성은 요금이 든다)
npm run art -- clip serin Move SE --from 0.5 --to 1.2    자동으로 잡은 구간이 어색하면 초 단위로 직접 지정
npm run art -- still serin                    영상 없이 기본 이미지 한 장을 정지 대기 동작으로 쓴다 (요금 없음)
npm run art -- pack serin                     프레임을 고친 뒤 시트만 다시 만든다
```

- **준비물**: Codex CLI 로그인(`codex login`), `.env.local` 의 `ARK_API_KEY`(BytePlus ModelArk), ffmpeg. `.env.local` 은 저장소에 올라가지 않는다.
- **비용**: 영상 한 편(1:1, 480p, 4초)이 Seedance 2.5 기준 약 0.42달러다 (캐릭터 한 명의 동작 10종이 약 4.2달러). `all` 은 `--yes` 없이는 아무것도 만들지 않고 계획과 예상 비용만 보여 준다. 이미 만든 것은 건너뛴다. Codex 이미지 생성은 ChatGPT 요금제 사용량에서 차감된다.
- **프레임 수 바꾸기**: `clips.csv` 의 frames 를 고치고 `clip` → `pack` 만 다시 돌린다. 영상을 다시 만들지 않으므로 요금이 들지 않는다.
- **무기가 잘릴 때**: 3단계에서 "그림이 영상 가장자리에 닿았습니다"가 나오면 휘두른 무기가 화면 밖으로 나간 것이다. `settings.csv` 의 `video.inset` 을 줄이고(여백이 넓어진다) `video <id> <동작> --force` 로 그 영상만 다시 만든다.
- **영상 없이 먼저 넣어 보기**: 기본 이미지만 만들고 `still` → `pack` 을 하면 정지 그림으로 게임에 들어간다. 그림체와 크기를 먼저 확인한 뒤 영상을 만들 수 있다.
- **확인**: 3단계가 끝나면 프레임 폴더에 `preview.gif`(움직임)와 `preview.png`(프레임 나열, 노란 선이 발밑)가 생긴다.
- **게임 반영**: 4단계가 끝나면 `public/sprites/index.json` 에 등록되고, 등록된 캐릭터·몬스터만 스프라이트로 그려진다. 아직 없는 동작은 가까운 동작으로 대신한다 (예: 이동 그림이 없으면 대기 그림).
- **표**: `data/art/` 의 CSV에서 고친다.

| 파일 | 내용 |
| --- | --- |
| subjects.csv | 만들 대상. 원화 파일, 배경색(캐릭터에 없는 색), 게임에서의 키, 방향, 외형·무기 설명 |
| clips.csv | 동작 목록. 반복 여부, 구간 찾는 방식, 프레임 수, 재생 속도, 영상 길이, 타격 지점(auto 면 가장 빠르게 움직이는 순간), 끝 프레임 고정 여부, 발 높이 보정 여부, 영상 속 이펙트(trail 이면 흰 검기 허용), 동작 설명. who 칸에 캐릭터 id를 적으면 그 캐릭터만의 동작이 된다. `BasicAttack1`, `BasicAttack2` …는 기본 공격 연속기의 단계별 동작이다 |
| settings.csv | 영상 모델·해상도·여백, 배경 제거 세기, 프레임 고르는 방식, 시트 크기 |

원화(`art/ref/`)와 영상 원본(`art/work/*/video/*.mp4`), 잘라낸 프레임은 용량과 공개 범위 때문에 저장소에 올리지 않는다. 영상을 지우면 다시 만들 때 요금이 드니 따로 보관한다.

방향은 화면 기준 이름이다 (`S` = 아래쪽, 카메라를 향함). 지금은 앞쪽 사선(`SE`) 한 방향만 만들고 좌우 반전해 쓴다. subjects.csv 의 dirs 에 방향을 더 적으면(예: `SE NE`) 그 방향 그림도 만든다.

## 폴더 구조

```
art/             스프라이트 원본: 원화(ref/), 기본 이미지·영상·프레임(work/)
data/            수치 테이블(CSV)과 고정 맵
  art/           스프라이트 제작 표
public/sprites/  게임이 읽는 스프라이트 시트
docs/            기획서
src/
  core/          난수, 수학, CSV 파서
  data/          테이블 읽기·검사
  game/          규칙 (화면을 그리지 않는다)
    world/       맵, 충돌, 무작위 배치, 전투 월드
    player/      파티 조작, 캐릭터 상태, 캐릭터별 스킬(kits/)
    enemy/       몬스터 상태와 행동 규칙
    pet/         펫 스킬
    run/         런 상태, 능력치 계산, 섹터 구성
  render/        PixiJS 표시부
    views/       캐릭터·몬스터 표시부 (도형 플레이스홀더와 스프라이트). registry.ts 가 고른다
    sprites/     스프라이트 시트 읽기, 방향·프레임 선택
  input/         터치·키보드 입력
  ui/            HUD와 메뉴 (HTML 오버레이)
tests/           규칙 코드 테스트
tools/           맵 생성, 브라우저 확인 도구, 스프라이트 제작 도구(art/)
```

규칙 코드(`src/game/`)는 화면과 분리돼 있어, 그림을 바꿔도 규칙 코드는 건드리지 않는다. 스프라이트 시트가 등록된 캐릭터는 스프라이트로, 나머지는 도형으로 그려진다.

## 배포

`main` 브랜치에 푸시하면 GitHub Actions가 테스트·빌드한 뒤 결과물을 `gh-pages` 브랜치에 올린다.
GitHub 저장소 설정의 Pages에서 `gh-pages` 브랜치를 소스로 지정하면 `https://<계정>.github.io/tarcov/` 로 접속할 수 있다.
